# Forms checklist

- Associate visible labels and instructions programmatically; placeholder text
  is not a label.
- Communicate required state in text as well as programmatically.
- Use appropriate `autocomplete` tokens for known personal-data purposes.
- Group related choices with native fieldsets and legends when suitable.
- Connect errors with `aria-describedby` or native mechanisms and mark invalid
  controls accurately.
- Place focus or an error summary so failed submissions are discoverable without
  disorienting users.
- Announce asynchronous status once, after the state is ready.
- Avoid asking for information already supplied in the same process without an
  allowed reason.
- Permit password managers and paste; provide an accessible authentication
  alternative where needed.
