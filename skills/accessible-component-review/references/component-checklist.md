# Component checklist

For each state, examine element choice; computed name, role, value, and state;
established keyboard interaction; visible focus including forced colors;
information conveyed by color; motion under `prefers-reduced-motion`; target
size and spacing; status/state announcements; and the difference between
disabled and read-only behavior.

Use the [WAI-ARIA Authoring Practices](https://www.w3.org/WAI/ARIA/apg/) only
for a widget whose required behavior cannot be represented by native HTML. Test
the implemented behavior rather than copying example markup.
